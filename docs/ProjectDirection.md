# Campus Agent 校园学习助手需求文档 

## 1. 项目定位 

面向大学生，将分散在课表、教学平台和聊天通知中的学习事务汇总为可管理的任务，减少信息遗漏并辅助学习安排 

核心流程：导入信息 → 提取任务 → 用户确认 → 统一待办 → 到期提醒 → 标记完成 

## 2. 项目目标 

- 汇总课程、作业、考试和通知，降低用户在多个平台间查找信息的成本 
- 利用大模型提取行动要求和截止时间，并保留原始来源供用户核对 
- 采用模块化设计，基础功能稳定后再扩展长期记忆、学情分析和笔记整理 
- 目标平台为 iOS、Android 和 HarmonyOS，首批用户是否仅限杭电学生待确认 

## 3. 首版基础功能 

### 3.1 课表管理 

- 支持课表导入和手动录入，具体导入格式待确认 
- 课程信息包括课程名称、教师、地点、上课时间及适用周次 
- 支持按日或按周查看课程，并将任务关联到课程 

### 3.2 信息导入与任务提取 

- 支持手动粘贴通知或聊天文本，作为首版可靠的信息入口 
- 提取任务名称、所属课程、截止时间、任务说明和来源 
- 保留原文与提取结果，用户核对、编辑并确认后保存为正式任务 
- 缺失时间或出现“下周五”等相对日期时，结合消息时间解析并提示用户确认，不能静默猜测 
- 自动接入外部平台的能力逐一验证，不以所有平台接入成功作为首版前提 

### 3.3 统一待办 

- 集中展示作业、考试准备及其他学习事务，支持新增、编辑、删除和标记完成 
- 支持按课程、截止时间和完成状态筛选，区分待完成、已完成与已逾期 
- 重复导入时提示可能重复，来源更新时保护用户已手动修改的内容 

### 3.4 基础提醒 

- 基础提醒纳入首版，复杂推送渠道作为可选扩展 
- 用户可设置、修改和取消提醒，首版优先实现本地提醒 
- 通知权限关闭或提醒设置失败时，在应用内展示状态 
- 通知、后台运行和提醒可靠性需要分别在三端验证 

### 3.5 基础设置 

- 支持配置学期起始日期、课表时间规则和默认提醒偏好 
- 支持查看和删除已导入的内容及任务 

## 4. 数据源接入规划 

| 数据源 | 计划用途 | 接入前提与边界 |
| --- | --- | --- |
| 杭电助手 SDK | 验证课表等校园数据获取能力  | 确认接口范围、授权方式、服务可用性及使用许可  |
| 学习通、泛雅 | 获取课程通知与作业信息  | 确认目标学校实际使用方式、两者关系与接口权限，避免重复建设  |
| 教务系统 | 获取课表及其他获授权的学业数据  | 按学校验证，不预设接口通用  |
| 钉钉 | 优先研究的聊天信息来源及提醒渠道  | 分别验证接收与发送能力，不预设能读取任意群聊或历史记录  |
| QQ、微信 | 可选信息来源  | 优先支持用户主动粘贴、分享或导入，自动接入另行验证  |

各数据源应展示最近同步时间及失败原因，接口不可用时保留手动导入入口 

## 5. 可选扩展模块 

### 5.1 用户需求与长期记忆 

- 允许用户录入学习目标、时间安排和个人偏好，用于个性化建议 
- 用户可查看、修改和删除记忆，区分主动填写的信息与系统推断的信息 
- 不默认永久保存全部聊天，保存范围和期限需明确设计 

### 5.2 学情梳理与学业指导 

- 根据实际获得的课程、任务完成情况及用户提供的数据整理学习概况 
- 生成周计划、复习建议和任务优先级建议，并说明依据及数据缺口 
- 涉及学分、考试和毕业要求时，应引用可靠来源并供用户核对 

### 5.3 笔记与识图 

- 支持文本笔记、图片导入及笔记与课程关联 
- 使用独立 OCR 或经验证的视觉服务识别图片，生成可编辑的电子笔记 
- 保留原图供核对，不预设所选 DeepSeek 模型具备图像识别能力 
- 手写文字、公式识别范围和笔记导出格式待确认 

### 5.4 扩展通知 

- 按需增加服务端推送、钉钉通知和每日摘要 
- 支持通知频率、免打扰时段和渠道设置 

## 6. 技术与模块划分 

- ArkUI-X 作为三端共用界面的候选方案，版本、系统接口及构建条件需验证 
- 客户端负责展示、用户确认、导入交互、本地缓存及提醒设置 
- 服务端负责外部平台适配、模型调用、同步调度和必要的数据存储 
- 云端大模型计划使用 DeepSeek API，具体模型、输入限制与成本在接入时确认 
- 模型密钥保存在服务端，不写入客户端安装包 
- 模型负责生成结构化候选结果，程序负责日期与字段校验，用户确认后保存 
- 各数据源通过独立适配模块转换为统一记录，避免业务页面直接依赖外部平台 
- 基础模块包括课程、通知、任务、提醒和设置，扩展模块包括长期记忆、学情分析及笔记 

## 7. 数据与可靠性要求 

- 通知至少保留来源、原文、导入时间及可用的外部记录标识 
- 任务至少保留标题、关联课程、截止时间、状态、来源关联和提醒设置 
- 有明确时间的任务应记录时区，无明确时间时不得擅自生成确定截止时间 
- 同步需要处理重复、失败和来源内容更新，不应无提示覆盖用户修改 
- 仅向模型发送完成当前功能所需的信息，账号凭据和访问令牌不得混入提示词或普通日志 
- 跨设备同步、离线可用范围及数据保留期限待确认 

## 8. 首版验收标准 

1. 用户能导入或手动建立真实课表，并正确查看对应日期的课程 
2. 用户能粘贴真实作业通知，获得可编辑、可核对来源的任务提取结果 
3. 缺失或存在歧义的截止时间会被明确提示，由用户确认或修正 
4. 用户能将提取结果保存为任务，并完成、修改或删除任务 
5. 应用重启后已保存的数据仍然可用，重复导入不会无提示地产生重复任务 
6. 通知权限开启且满足受支持运行条件时，提醒按设置触发，任务修改或删除后旧提醒更新或取消 
7. 外部平台不可用时展示失败状态，用户仍能通过手动入口建立任务 
8. 三端分别记录验证结果，未经测试的平台不标为完成 

## 9. 实施顺序 

1. 验证数据源权限、课表导入方式和三端基础能力，确定首版边界 
2. 完成课表、文本导入、模型提取、用户确认、统一待办和基础提醒的完整流程 
3. 优先接入验证通过的校园数据源和钉钉能力，完善同步与异常处理 
4. 根据用户反馈扩展长期记忆、学情分析、笔记识图及其他消息来源 

## 10. 待确认事项 

- 首批用户是否仅限杭电，是否计划支持其他学校 
- 项目用于课程展示、比赛演示还是长期运营，团队规模和交付期限是什么 
- 首版必须自动接入哪些来源，是否已有接口权限和测试账号 
- 三端是否同时交付，是否具备各平台构建与真机测试条件 
- 是否需要注册登录和跨设备同步，服务端与模型预算是多少 
- 课表首版导入格式、笔记后续导出格式分别是什么
